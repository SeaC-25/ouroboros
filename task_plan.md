## Decisions
- Analyze local source only; do not perform live network testing.
- Extract archives into `.analysis/` to avoid mutating project archives.
- New architecture direction: learn design philosophy from Kali-MCP, Eidolon, and Xalgorix, but do not preserve their runtime architecture.
- Main design primitives are Goal Stack, Sisyphus Engine, Evidence Graph, Tool Compiler, and Web/API, Infra/Internal, CTF/Lab domain packs.
- Current design pass is capability-first and focuses on platform architecture, runtime, UI, and toolchain behavior.
- Project branding now uses `docs/assets/ouroboros-logo.png` as the stable documentation asset copied from the root logo PNG, while the root PNG remains the local source image.
- New study phase added for three additional local model archives; analyze source only and extract into `.analysis/`.
- Production hardening now exposes deterministic `run --tui` and `replay --tui` snapshots before the full interactive TUI runtime is launched from CLI commands.
- Production hardening now launches Bubble Tea for `run --interactive` and `replay --interactive` from replay-derived TUI models; run-side live snapshot streaming and replay-side timeline cursor setup are wired through the shared replay projection.
- Safety bypass authorization expiry is treated as a current-validity control: expired `authorization.yaml` bypass entries remain auditable but do not satisfy strict gates, and restored `scope.target_policy: enforce` / `execution.isolation: process|container` removes TUI bypass rows.
- Run-level safety bypass audit and optional strict run gating are implemented: each run writes `workspace_safety`, default runs remain warning-only, and `run --require-safety-authorization` blocks missing or expired disabled-boundary authorization before execution/report side effects while preserving the close/off path.
- Runtime-worker safety-bypass authorization is implemented at ten direct app side-effect gates: queue-claim dispatch, file-outbox acknowledgement, worker transport request-command execution, worker queue dispatch result submission, worker dispatch retry-dispatch execution, active-lease heartbeat refresh, active-lease release, stale-lease reclaim execution, lease/result reconciliation execution, and opt-in daemon-control consumption in `ExecuteRuntimeWorkerTransportDispatchDaemon`. Higher-level worker paths inherit this only when they delegate through those gates; the supervisor inherits daemon-control protection through child daemon runs and is not counted as a separate direct gate. HTTP receive/artifact ingress, daemon-control creation/list/read, ordinary run lease acquire/complete writes, and metadata-only read/review paths remain separate follow-up candidates.
- Command-runner embedded target-literal hardening is implemented for key/value and comma-list arguments across URL, CIDR/IP, and challenge targets, while preserving `scope.target_policy: disabled` as the explicit authorized off path.
- Production hardening now has the first live streaming foundation: run observers receive durable events and replay snapshots, and the TUI model can apply replay snapshot messages through `Update`.
- `run --interactive` now sends live replay snapshot messages from `RunWorkspaceWithOptions.OnSnapshot` into the active TUI session; real long-running worker/tool execution is still pending.
- `run --interactive` now has a double-confirm cancel control through the TUI model: `c` arms confirmation, the second `c` invokes a runtime control requester wired to the CLI run context cancel function, and Agent Runtime rows retain cancel feedback.
- `run --interactive` now also supports pause/resume through the same runtime control requester: `p` pauses new worker admission, queued workers emit `wait_reason: run_paused`, and the next `p` resumes admission.
- Replay timeline controls now exist at the TUI model level: `ReplayTimelineMsg` loads persisted events, left/right keys move an event cursor, and snapshots are rebuilt deterministically for the selected point.
- App and CLI replay paths now return/launch replay-event-backed TUI models, so timeline cursor controls are reachable through `replay --interactive`.
- Timeline Lanes now exposes replay cursor controls visibly: active timeline tab, lane-count bars, current event id/type/lane, prev/current/next event context, and left/right plus home/end key hints.
- `ouro replay` now supports read-only alternate export formats through `--format json`, `--format ndjson`, and `--format html`; JSON emits run/status/lane/timeline metadata in one document, NDJSON emits one timeline event per line, HTML emits a self-contained canvas timeline, and non-text exports cannot be combined with `--tui` or `--interactive`.
- `ouro replay-workbench <workspace> <run-id>` now serves a local read-only hosted replay workbench from the same export data: `GET /` returns HTML/canvas, `GET /api/replay` returns the primary run JSON, `GET /api/replays` returns the primary plus repeatable `--compare-run` JSON exports, `GET /api/timeline.ndjson` returns the primary timeline NDJSON, `GET /api/session` returns a shareable URL/session projection, and `GET /api/sessions` returns saved workbench session artifacts. The JSON/NDJSON APIs accept read-only `?lane=` and `?q=` filters, and the HTML embeds `window.OURO_REPLAYS`, `window.OURO_REPLAY_SESSION`, and `window.OURO_REPLAY_SESSIONS` with run/session selectors, local lane/search controls, and URL-state synchronization. Non-GET methods are rejected, and `--max-requests` can bound the server for tests or supervised runs without invoking run/dispatch/transport/worker-control paths.
- Hosted replay workbench now adds read-only Evidence Graph projection through `GET /api/graph`, `GET /api/graphs`, `GET /api/graph.ndjson`, `window.OURO_REPLAY_GRAPHS`, and an HTML graph canvas/list. Graph search filters node and edge metadata, `?node=<id>` focuses a one-hop neighborhood, `?edge=<id>` focuses one edge plus its endpoints, graph exports and NDJSON summaries carry focus metadata, and the HTML exposes graph summary plus selected node/edge detail panels. Graph URL/session state carries node/edge focus. The graph path does not create sessions, mutate artifacts, or invoke run/dispatch/transport/worker-control paths.
